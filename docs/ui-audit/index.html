SignMaker — segmented control inventory

Current PR #24 local changes · November 13, 2026 · Desktop and mobile comparison

Actual app controls, isolated for comparison with their computed styles frozen into DOM copies. Deferred widgets are initialized before capture. These are control specimens, not screenshots of complete screen layouts. No product source styling was changed for this audit.

Current default dark theme. Mobile uses a browser viewport, not simulator hardware safe areas. Selected states are the app’s initialized states.

Findings

Separate implementations exist for editor tabs, shared alignment widgets, shield/icon alignment, arrow choices, Exit Only modes, default font/alignment/rotation choices, custom shield choices, and asset-source tabs. Panel-style tabs override the styling of the same tab class used elsewhere.

Heights, gaps, border treatments, selection colors, and state attributes differ. Mobile commonly raises button heights to 44px while desktop controls use several smaller sizes. Exit-tab profile mode is intentionally hidden on mobile. Custom shield authoring is also unavailable through the mobile UI; its specimens are included to show the full source inventory.

Shared alignment instances: text, grouped block, blocker, advisory, beacon, arrow block, toll logo, action message, electronic sign, exit-tab position, exit-marker position, shield placement, and post position. These reuse AlignmentButtons.js; specimens 6–8 show that implementation.

Legacy CSS: .settingsSegmentedRow / .settingsSegmentButton still exist in form.css, but no current HTML or JavaScript instantiates them. They should not be counted as a live fourth style. Single toggles, dropdowns, and action rows (Add/Duplicate/Delete, Copy/Export) are excluded.

Unification direction: one shared segmented-control primitive with text/icon content, consistent active/disabled/focus states and keyboard behavior; one desktop density and one mobile touch density. Keep tabs and multi-select export semantics distinct even if their visual tokens are shared.

Individual crops and measured styles: inventory.json. Source selectors are printed on each card.
